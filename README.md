# Python 自动化项目集

本项目包含两个贴吧图片采集脚本和一个微信家教订单监控脚本，主要涉及网页采集、浏览器自动化、消息增量处理、规则筛选、地图服务调用和通知推送。

## 项目结构

```text
專案/
├── xianyu_Crawler.py
├── selenium百度貼吧.py
└── 微信家教订单监控脚本.py
```

## 运行环境与依赖

建议使用以下运行环境：

- Python 3.10 或更高版本
- Google Chrome
- 与 Chrome 版本兼容的 ChromeDriver；新版 Selenium 通常可以通过 Selenium Manager 自动管理驱动

安装 Python 依赖：

```powershell
python -m pip install -r requirements.txt
```

主要第三方依赖：

| 依赖 | 用途 |
| --- | --- |
| `selenium` | 启动 Chrome、处理动态页面和图片懒加载 |
| `requests` | 请求网页、下载图片和调用第三方 HTTP API |
| `beautifulsoup4` | 解析贴吧搜索结果 HTML |
| `lxml` | 为 BeautifulSoup 提供 HTML 解析器 |
| `pandas` | 生成帖子图片采集统计 CSV |
| `pyproj` | 根据经纬度计算两点之间的直线距离 |

其中，两个贴吧脚本需要 Chrome；微信家教订单监控脚本不需要浏览器，但需要本地微信数据接口、高德地图 Key、腾讯地图 Key 和飞书机器人 Webhook。

## 1. xianyu_Crawler.py

### 功能

这是一个以 Selenium 为主的贴吧图片采集脚本。程序自动遍历搜索结果页，收集帖子链接，进入帖子页面触发图片懒加载，再通过 requests 下载符合条件的原图。

### 处理流程

```text
读取运行配置
  → 启动 Chrome
  → 注入可选的百度 Cookie
  → 遍历贴吧搜索结果页
  → 提取并去重帖子链接
  → 逐个打开帖子并滚动页面
  → 提取原图地址
  → 同步浏览器 Cookie 到 requests.Session
  → 下载并保存图片
  → 记录错误并关闭浏览器
```

### 设计思路

- Selenium 负责需要浏览器环境的页面访问、Cookie 注入和懒加载触发。
- requests 负责图片二进制下载，避免所有网络请求都经过浏览器。
- 使用 `requests.Session` 复用连接，并同步 Selenium 的登录状态。
- 帖子链接在采集阶段去重，避免重复处理相同页面。
- 页面、帖子和单张图片分别处理异常，局部失败不会终止整个任务。
- 使用 `finally`、退出钩子和终止信号统一释放 Chrome 进程。
- Cookie 和输出目录通过环境变量配置，不依赖固定的个人电脑路径。

### 主要配置

| 环境变量 | 作用 |
| --- | --- |
| `BAIDU_COOKIE` | 可选的百度登录 Cookie；未设置时使用匿名会话 |
| `IMAGE_OUTPUT_DIR` | 图片保存目录，默认是脚本目录下的 `images` |
| `START_IMAGE_INDEX` | 图片文件的起始编号 |

## 2. selenium百度貼吧.py

### 功能

这是一个分阶段的贴吧图片采集脚本。第一阶段使用 requests 和 BeautifulSoup 解析搜索结果，第二阶段使用 Selenium 打开动态帖子页面，最后下载图片并生成每个帖子的采集统计。

### 处理流程

```text
requests 请求搜索结果页
  → BeautifulSoup 解析帖子链接
  → 拼接完整 URL 并有序去重
  → 启动 Chrome
  → 注入并同步 Cookie
  → Selenium 打开帖子并触发懒加载
  → requests 下载原图
  → 统计每帖图片数量和成功下载数量
  → 输出 CSV 统计文件
  → 关闭浏览器
```

### 设计思路

- 搜索结果页主要是静态 HTML，使用 requests 获取速度更快、资源开销更低。
- 帖子详情页包含动态渲染和图片懒加载，因此使用 Selenium 处理。
- 静态页面与动态页面采用不同工具，减少不必要的浏览器操作。
- 使用集合判断链接是否重复，同时用列表保留稳定的处理顺序。
- 下载请求携带当前帖子地址作为 Referer，并复用浏览器会话 Cookie。
- 每个帖子记录发现图片数和成功下载数，便于区分解析问题与下载问题。
- 统计结果使用 UTF-8-SIG 编码写入 CSV，可直接使用常见表格软件查看。

### 与第一个脚本的区别

| 对比项 | xianyu_Crawler.py | selenium百度貼吧.py |
| --- | --- | --- |
| 搜索页采集 | Selenium | requests + BeautifulSoup |
| 帖子详情页 | Selenium | Selenium |
| 图片下载 | requests | requests |
| 统计输出 | 下载数量 | 每帖明细与 CSV |
| 侧重点 | 完整浏览器流程 | 静态与动态任务分层 |

## 3. 微信家教订单监控脚本.py

### 功能

该脚本定时读取本地微信数据接口中的群聊消息，从固定格式的家教订单文本中提取科目、年级、报价、地址和老师要求，再结合业务规则与通勤距离筛选订单，将符合条件的内容推送到飞书。

### 整体流程

```text
加载配置和本地缓存
  → 调用本地接口同步微信数据
  → 分页读取指定群当天的消息
  → 根据每个群的 last_seq 获取增量消息
  → 按 seq 去重和排序
  → 解析订单字段
  → 执行科目、年级、报价等基础规则
  → 对线下地址进行地理编码
  → 使用直线距离进行第一轮筛选
  → 对中等距离地址查询驾车时间
  → 推送符合条件的订单到飞书
  → 保存消息游标和地图缓存
```

### 订单解析思路

消息中的字段采用统一格式，例如：

```text
【补习科目】
【学生年级】
【报价】
【地址】
【对老师要求】
```

程序通过正则表达式定位字段边界，并对结果进行规范化：

- 科目会去除人数、数量词和常见分隔符，再与允许科目列表进行完整匹配。
- 年级会区分高中、初中和小学，避免只依赖单个数字判断。
- 报价字段提取整数，并以字段中的最高报价作为判断值。
- 地址会移除括号内容和“附近、门口、对面”等干扰词，再统一补充城市前缀。
- 老师要求会识别仅限男性等不符合条件的情况。

### 距离筛选思路

地图处理采用分层判断，避免每条消息都直接调用路线规划接口：

1. 先将订单地址转换为经纬度。
2. 使用 `pyproj.Geod` 在本地计算直线距离。
3. 距离很近的订单直接通过。
4. 明显过远的订单直接拒绝。
5. 只有中间距离的订单才请求驾车路线和预计时间。

这种处理方式减少了外部 API 调用次数，也缩短了大部分订单的判断时间。

### 双地图服务设计

- 高德地图负责主要的地理编码、POI 搜索和路线规划。
- 腾讯地图作为后备服务，在高德失败或结果不足时继续处理。
- 两个服务使用独立限流器，控制连续请求的时间间隔。
- 地理编码和驾车结果分别保存到本地缓存，重复地址不需要再次请求。
- 驾车缓存同时保存起点和终点坐标，坐标发生变化时不会错误复用旧结果。
- 批量地址通过两个工作线程并行处理，失败任务会转交另一个地图服务。

### 消息游标设计

程序为每个监控群保存独立的 `last_seq`：

- 只处理序号大于当前游标的新消息。
- 新消息先去重，再按序号从小到大处理。
- 普通拒绝订单完成判断后推进游标。
- 飞书推送失败时保留当前游标，下一轮继续重试。
- 地图服务暂时无法确认地址时不推进游标，避免直接漏掉订单。
- 非文本消息会正常提交游标，防止阻塞后续消息。

该设计更偏向“允许少量重复重试，也尽量避免漏处理”。

### 缓存与并发安全

- `last_seq_dict.json` 保存各群的消息处理位置。
- `dist_cache.json` 保存地址坐标、直线距离和结果可信度。
- `driving_cache.json` 保存驾车距离与预计时间。
- JSON 文件先写入临时文件，再通过 `os.replace` 原子替换，降低写入中断造成文件损坏的风险。
- 内存缓存、驾车缓存和文件写入分别使用锁保护。
- 每个工作线程使用独立的 `requests.Session`，同时复用连接并避免共享会话状态冲突。

### 异常处理

- 本地数据同步失败时自动重试，不推进消息游标。
- HTTP 请求均设置超时时间，避免外部服务长时间无响应。
- 同类错误通知设置最小间隔，防止飞书出现重复告警。
- 主循环发生异常时保存当前状态，并以非零状态退出，便于外部进程重新启动。
- 空闲时降低同步频率，出现新消息后提高同步频率。
- 到达设定时间后自动保存状态并停止。

### 主要配置

| 环境变量 | 作用 |
| --- | --- |
| `FEISHU_WEBHOOK` | 飞书机器人 Webhook |
| `AMAP_KEY` | 高德地图 API Key |
| `TENCENT_KEY` | 腾讯地图 API Key |
| `WETRACE_API_BASE` | 本地微信数据接口地址 |
| `HOME_ADDRESS` | 计算通勤距离使用的起点地址 |
| `TALKER_IDS` | 需要监控的群聊 ID，多个值使用逗号分隔 |

## 共同设计原则

- 将浏览器渲染、HTTP 请求、内容解析和文件保存拆分为独立步骤。
- 对外部请求设置超时，并将单个任务失败限制在局部范围内。
- 使用 Session 复用网络连接，减少重复握手开销。
- 使用环境变量管理账号会话和第三方服务配置。
- 对可重复使用的数据进行缓存，降低网络请求次数。
- 在程序退出或异常时保存必要状态并释放浏览器资源。
